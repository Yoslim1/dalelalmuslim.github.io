# أساس إعادة بناء «دليل المسلم»

**الحالة:** وثيقة تنفيذية معتمدة قبل إعادة بناء الواجهة.  
**المنصة الحالية:** Expo SDK 54 / React Native / Expo Router / TypeScript.  
**حد المنتج:** محلي أولًا؛ لا حسابات ولا خادم مطلوبان للتجربة الأساسية. ملفات التلاوة تنزيل اختياري فقط.

> الغاية ليست زيادة عدد الصفحات. الغاية أن تكون التجربة العربية الهادئة واضحة وسريعة وموثوقة، وتعيد المستخدم مباشرةً إلى عبادته أو آخر موضع نافع له.

## 1. نتائج التدقيق التي تحكم التنفيذ

| المجال | الحالة المرصودة | القرار |
|---|---|---|
| تنزيل التلاوة | يفشل Android أثناء تمرير `ArrayBuffer` إلى `expo-crypto`، فتظهر رسالة Kotlin خام ولا يصل المستخدم إلى «تشغيل». | إصلاح مسار البصمة واختباره رجعيًا قبل أي توسعة تصميمية صوتية. تُترجم كل الأخطاء إلى حالات مفهومة. |
| التنقل | خمسة تبويبات بينها «المزيد» الذي يجمع أدوات غير مترابطة. | أربعة تبويبات ثابتة: **الرئيسية، القرآن، الأذكار، الأدعية**. الإعدادات زر واضح في رأس الرئيسية؛ الأدوات الثانوية تظهر في «أدوات اليوم» وفي الإعدادات وفق وظيفتها. |
| الرئيسية | شبكة بطاقات كبيرة ومتماثلة، وفراغ بصري كبير، ولا تعطي أولوية واضحة للعبادة التالية. | مركز عبادي يومي قائم على الاستئناف والتقدم والاختصارات السياقية؛ لا يعرض كل ميزة كبطاقة متساوية. |
| التصميم | `palette` لون واحد فاتح مع قيم حرة في المكونات، وحدود وظلال أكثر من اللازم في بعض الشاشات. | نظام tokens دلالي للفاتح والداكن؛ أسطح tonal لا بطاقات محاطة دائمًا؛ 4/8dp spacing وكتابة عربية قابلة للتمدد. |
| الأخطاء | طبقات الملف/التشفير تمرر رسائلها الخام إلى الواجهة. | تترجم طبقة المجال الخطأ إلى `AudioDownloadError` محدود؛ الواجهة لا تستقبل استثناءً خامًا أبدًا. |
| الحالة | `AppState` المحلي قابل لإعادة الاستخدام، لكن الإعدادات محدودة ولا توجد حالة موحدة لتنزيلات الصوت أو تفضيلات القراءة المتقدمة. | توسيع schema بهجرة صريحة وباختبارات، لا إضافة Context أو store منافس. |

## 2. خريطة المنتج والتنقل

```text
الجذر (AppStateProvider → ReciterLibraryProvider → QuranAudioProvider)
│
├─ تبويب: الرئيسية
│  ├─ متابعة القراءة / آخر عبادة
│  ├─ تقدم اليوم
│  ├─ آية اليوم ورسالة قصيرة
│  ├─ اختصارات: المسبحة، المهام، أسماء الله، القصص، الإحصاءات
│  └─ زر الإعدادات
├─ تبويب: القرآن
│  ├─ استئناف القراءة
│  ├─ السور / البحث
│  ├─ القارئ والتلاوات المتاحة
│  └─ قارئ السورة + مشغل مصغر عند وجود Track
├─ تبويب: الأذكار
│  └─ المجموعات → قراءة الذكر → تقدم محفوظ
└─ تبويب: الأدعية
   └─ الفئات → الدعاء → حفظ/نسخ/مشاركة

مسارات Stack: المسبحة، المهام، الإحصاءات، أسماء الله، القصص، الإعدادات، مكتبة التلاوات، تفاصيل السور/الأذكار/الأدعية.
```

لا يبقى مسار «المزيد». تُحافَظ على الروابط العميقة الحالية للمسارات الثانوية، ثم يُعاد توجيه أي وصول داخلي إلى المكان المقصود بدل ترك تبويب فارغ.

## 3. حدود الميزات ومسؤوليات الملفات

| الحد | مسؤولية الواجهة | الحالة والبيانات | ممنوع |
|---|---|---|---|
| `features/home` | عرض العبادة التالية والملخص والاختصارات. | selectors صرفة فوق `AppState` و`daily.ts`. | استيراد ملفات المحتوى الخام أو طبقة تنزيل الصوت مباشرةً. |
| `features/quran` | الفهرس والقارئ والـmini player. | `ReciterLibraryProvider` و`QuranAudioProvider` وbookmark. | تحويل الأخطاء الخام أو حساب البصمات في React component. |
| `features/audio` | إدارة القارئ والتنزيلات وحالة الملف. | manifest موثّق، file adapter، typed errors. | الادعاء بتوافر سور غير منشورة أو تنزيل كل القرآن بينما المتاح فاتحة فقط. |
| `features/dhikr` | قائمة المجموعات وقارئ الذكر والتقدم. | `azkarRepeats` و`completedAzkarIds`. | تكرار منطق التقدم في الرئيسية. |
| `features/tasbih` | منطقة لمس كبيرة، عداد، إعادة ضبط، haptics اختيارية. | `daily.tasbeehCount` وsettings. | مؤثرات مستمرة أو اهتزاز مزعج كل مرة. |
| `features/settings` | المظهر، القراءة، الصوت، haptics، البيانات والخصوصية. | `settings` و`audio` بهجرة schema. | مسح البيانات دون تأكيد واضح أو تغيير حالة مباشرة بلا حفظ. |

يستمر `components/` للمكونات المرئية الخالصة فقط، و`lib/` للخدمات والمحوّلات والنماذج الصرفة. لا تُنشأ طبقة repository أو state manager جديد إلا إذا أثبتت الحدود أعلاه عجز الموجود الحالي.

## 4. نموذج الحالة والبيانات

كل تدفق غير فوري يستخدم اتحاد حالات صريحًا بدل مجموعة booleans:

```ts
type AsyncState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "ready"; data: T }
  | { status: "empty" }
  | { status: "error"; error: UiError };

type AudioDownloadError =
  | "network"
  | "storage"
  | "integrity"
  | "unsupported"
  | "unknown";
```

تُحفظ فقط بيانات المستخدم اللازمة محليًا: آخر آية، تكرار الأذكار، المفضلة، المقروء، المهام، التلاوة المختارة، سرعة التشغيل، إعدادات العرض، وبيانات التنزيلات. تظل النصوص الدينية المضمّنة ثابتة ومصحوبة بمصادرها، وتتحقق فهارس الصوت قبل التشغيل.

## 5. نظام التصميم «سَكينة»

### الفكرة المميزة

**أثر السجادة الهادئ:** فصل الأقسام بخطوط هندسية دقيقة جدًا أو أقواس مسطحة عند الحاجة، لا كخلفية زخرفية مستمرة. تبدأ كل شاشة من «ما الذي يعود إليه المستخدم الآن؟» لا من لوحة معلومات عامة.

### الرموز الدلالية المقترحة

| الدور | فاتح | داكن | الاستخدام |
|---|---:|---:|---|
| `surface` | `#F8FAF8` | `#101614` | خلفية الشاشة |
| `surfaceContainer` | `#EEF5F1` | `#18221E` | مجموعات وأشرطة ثابتة |
| `surfaceRaised` | `#FFFFFF` | `#202D27` | بطاقات مركزة فقط |
| `primary` | `#176B5B` | `#79D2BD` | الإجراء الأساسي والحالة المختارة |
| `onSurface` | `#132C25` | `#E7F2EC` | النص الرئيس |
| `onSurfaceVariant` | `#5A7068` | `#B5C9C0` | النص الثانوي |
| `tertiary` | `#A97B25` | `#E4BD67` | إبراز قليل مثل آية اليوم، لا للزينة العامة |
| `error` | `#B33E47` | `#FFB3B8` | الأخطاء والإجراءات المدمرة |
| `outlineVariant` | `#D8E3DD` | `#3A4D45` | فواصل رفيعة عند الحاجة |

**الطباعة:** خط النظام العربي أولًا لتقليل الحجم وتحسين اتساق Android، مع مقاييس: label 12–13، body 16/26، title 20–22، headline 28–32. نص القرآن يحتفظ بإعداد مستقل لاحقًا ولا يخلط بخط عناصر التحكم. لا تستخدم قيمة نص دون 14 للحالات المهمة، ولا لونًا وحده للدلالة على الحالة.

**الشكل والمسافات:** مقياس 4/8dp؛ زوايا 12 للمجموعات، 16 للبطاقات المركزة، 24 للـsheet، وfull للأزرار/chips. لا تستعمل حدودًا حول كل عنصر؛ تُستعمل الأسطح اللونية والفواصل الهادئة لإظهار البنية. جميع الأهداف التفاعلية لا تقل عن 48dp على Android.

**الحركة:** ضغط 80ms بتعتيم خفيف وscale إلى 0.98 دون تغيير حدود العنصر. انتقالات 200–300ms، ولا حركة مستمرة. تحترم الخيارات اللاحقة لتقليل الحركة. اتجاه الانتقال للأمام/الخلف يراعي RTL؛ عناصر الوسائط والزمن تظل LTR وظيفيًا.

## 6. معايير القبول العامة لكل ميزة

لا تغادر أي ميزة مرحلة التنفيذ قبل تحقق البنود الآتية:

| جانب | الحد الأدنى المطلوب |
|---|---|
| التصميم | شاشات loading/empty/error/success لا تترك فراغًا غير مفسر ولا تظهر استثناءً خامًا. |
| التفاعل | كل `Pressable` له 48dp، label وصولي، حالة ضغط، وعدم تعارض gestures. |
| Offline | المحتوى الأساسي يفتح محليًا؛ تنزيل التلاوة اختياري مع ملف سليم فقط. |
| RTL | النص والترتيب والتنقل عكس LTR؛ الزمن والتقدم الصوتي LTR. |
| الإتاحة | تكبير الخط لا يقص المحتوى، الألوان لا تحمل الحالة وحدها، وTalkBack يسمي الإجراءات. |
| الأداء | `FlatList` للقوائم، تجنب رسم الخلفيات النقطية والمتحركات الدائمة، ولا تحديث حالة خارج نطاقها. |
| الاختبار | وحدة للنموذج أو selector، واختبار تدفق للأخطاء الحرجة؛ ثم TypeScript وlint والاختبارات والتصدير قبل الادعاء. |

## 7. تسلسل التنفيذ و«بوابات» الاستقرار

1. **الصوت أولًا:** تصحيح SHA-256 لـAndroid، ترجمة الأخطاء، اختبار رجعي، وتحقق عملي: تنزيل → حفظ → تشغيل → إيقاف → إعادة فتح.
2. **الأساس:** tokens والسمات والحالة/الهجرة وApp shell وedge-safe layout.
3. **التنقل والرئيسية:** إزالة المزيد، تبويبات أربعة، home hub متوازن.
4. **القرآن:** القراءة النظيفة، فهرس أوضح، التلاوة والـmini player.
5. **الأذكار ثم المسبحة ثم الأدعية:** كل قسم يثبت حالة وتقدمًا وإتاحة قبل التالي.
6. **أسماء الله والمهام والقصص والإحصاءات:** إثراء السياق اليومي دون ازدحام.
7. **الإعدادات:** ظهور/خط/قراءة/صوت/haptics/بيانات وخصوصية.
8. **تدقيق نهائي:** وصول وأداء وoffline ولقطات هاتف وبناء APK مستقل واختبار جهاز فعلي.
